Blender 5.2.3 API notes for this project (verified by introspection on this machine)
====================================================================================
* Engine id: 'BLENDER_EEVEE' (EEVEE Next). Cycles exists but is NOT used (too slow on this laptop).
* 'Fac' sockets were renamed to 'Factor' (Noise/Brick/Wave/Gradient/Attribute/Fresnel outputs, MixShader/ColorRamp inputs).
* ShaderNodeMix: inputs 0=Factor(float) 2/3=A/B float, 4/5=A/B vector, 6/7=A/B color; outputs 0 float, 1 vector, 2 color.
* Materials/worlds: 'use_nodes' is deprecated but harmless; node tree always exists.
* Material EEVEE settings: surface_render_method ('DITHERED' | 'BLENDED'), use_transparent_shadow, use_backface_culling,
  displacement_method, volume_intersection_method, use_raytrace_refraction.
* Compositor: scene.compositing_node_group = bpy.data.node_groups.new(name, 'CompositorNodeTree'); final image goes to a
  NodeGroupOutput (interface socket of type NodeSocketColor), there is NO Composite node and NO scene.node_tree.
  CompositorNodeMixRGB / SunBeams / MapValue no longer exist (use ShaderNodeMix, Glare 'Sun Beams' type, ShaderNodeMapRange).
* Sky texture types: SINGLE_SCATTERING, MULTIPLE_SCATTERING, PREETHAM, HOSEK_WILKIE (no 'NISHITA').
* View transform 'AgX', looks are named 'AgX - Punchy', 'AgX - Medium High Contrast', ...
* Light: use_shadow, shadow_soft_size, use_custom_distance/cutoff_distance, shadow_maximum_resolution, use_shadow_jitter.
  IMPORTANT: many shadow-casting point lights overflow the EEVEE shadow pool and made a test render take 200 s and
  10 GB RAM. Only the sun (and at most a handful of hero lights) may cast shadows: set light.use_shadow = False.
* EEVEE speed on this machine (Radeon 780M): ~4-6 s per 1080p frame for a 2.5M-triangle scene with raytracing,
  +1.5 s with volumetrics. Keep shaders reasonably lean (noise Detail <= 6 where possible).
